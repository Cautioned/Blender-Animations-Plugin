# Post processing and built-in materials

The original 16-case visual report compares a legacy-material Studio place against synthetic Blender files that requested 2022 materials. The saved native `build/visual_parity/01_daylight.rbxlx` and `ParityReference.rbxlx` both declare **Use2022MaterialsXml=false**. The old fixture generator used the runtime name `Use2022Materials`; Studio ignores that XML property. The production decoder now accepts the serialized alias, retaining explicit false, with the runtime alias as fallback. The old report uses `reference_materials.json` to record its actual generation without changing its captures or the original binaries. Newly generated fixtures declare the native serialized name correctly.

This supplemental suite explicitly loads 2022 materials in a separate generated Studio place. It captures daylight, color correction, and an explicit BloomEffect with ordinary bright surfaces as well as Neon. The existing suite retains its 16 captures. These are image-error measurements, not a percentage of engine parity.

Run `python3 tools/post_material_parity/scenes.py`, open the generated `build/post_material_parity/01_daylight.rbxlx` in a separate Studio window, and run its marker-guarded case controllers. Use `tools/visual_parity/receiver.py --output build/post_material_parity/studio` with the capture controller from the existing visual suite. Capture Studio before rendering Blender. Its runtime material-generation property is restricted to engine scripts; native SerializationService also refuses MaterialService, so generation evidence is the loaded serialized property and visibly distinct material textures, rather than a fabricated property readback.

Render with `tools/visual_parity/render.py -- --root build/post_material_parity --scale .5 --samples 32`. `--output` accepts an absolute temporary directory; copy those results to `blender/` if OneDrive prevents the Blender process from overwriting files. Generate the report with `tools/visual_parity/compare.py --root build/post_material_parity`. Optional `--baseline-folder` compares images with the same camera, dimensions and original metrics.

The managed compositor applies source exposure once, then display-space tint, saturation, contrast and additive brightness. Enabled ColorCorrectionEffects compose; disabled controls and explicit zero values survive. Neon runs before grading. Explicit BloomEffects also affect non-Neon highlights, using a peak-channel threshold and an image-relative blur so saturated colors bloom. Reimports reuse owned stages, keep user grading/output consumers connected, and remove the grading stage when the next import has no active effects. A custom compositor with no scene render input stays untouched.

Built-in albedo alpha is sampled as a tint mask, with independent RGB preserving details at zero alpha. Glass keeps its separate color path. Tint masks blend white and tint in the measured display-space domain, then return linear RGB to the PBR shader; this avoids the overly pale intermediate-alpha result. The gamma 2.2 conversion is an engine approximation checked against native alpha-band captures. Color/data/transparency bindings have isolated image roles; late hydration keeps the packed-color role. MaterialVariant conversion retains its previous path pending additional native coverage. Tangent normal maps explicitly use the material UV layer. Sphere material UVs reconstruct the cube charts before radial rounding, including nonuniform spheres. Native OBJ derivatives verify all six chart orientations. Batched, individual, generic and non-NumPy imports use the same mapping, while decal/classic UVs retain their separate coordinates. Other triangulated material UVs share their projection anchors across triangles.

Limits: this pass verifies Blender 5.2.1 EEVEE and Studio 0.746, Realistic lighting at editor quality 21. Reflections, transmission, tone mapping, spatial ambient fill and bloom kernels still differ. Color correction's affine display fit approximates the engine. SunRays remains metadata; BlurEffect, DepthOfFieldEffect and full atmospheric/fog rendering are not implemented by this pass. Older Blender versions and Cycles need separate rendered verification.

Primary references: [Roblox color correction](https://create.roblox.com/docs/reference/engine/classes/ColorCorrectionEffect), [post effects](https://create.roblox.com/docs/environment/post-processing-effects), [materials](https://create.roblox.com/docs/parts/materials), and [albedo tint masks](https://create.roblox.com/docs/art/modeling/surface-appearance).

The follow-up sphere/alpha comparison lives in `build/sphere_material_parity/`. `alpha_mask_compare.py` compares six SurfaceAppearance tint colors and six Part transparencies against the original native captures. `test_sphere_materials.py` checks native chart derivatives and all import paths, including the Python UV upload fallback.
